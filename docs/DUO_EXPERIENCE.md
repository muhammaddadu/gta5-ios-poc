# Duo handheld experience

## Intended experience and constraints

Prepare a working native build without requiring the phone to be connected.
Landscape fills the available display with restrained touch overlays. Unfolded
portrait puts a separately rendered game view above a dedicated lower control
deck. A physical controller can reclaim the complete window. Controls must stay
reachable, respect safe areas, support simultaneous movement/camera/actions and
release held input across a display transition. Preserve Story and both
Playground choices and the existing app identity/data paths.

All sources below inspire interaction principles; no third-party skins or brand
artwork are copied into this repository. Game assets and generated native code,
previews, screenshots, archives and IPAs remain private under `.local/`.

## Single-session option exploration

| Mechanism | Candidate | Trade-off |
| --- | --- | --- |
| Conventional baseline | Translucent gamepad overlay in both orientations | Smallest change; thumbs cover portrait gameplay and controls spread too far apart. |
| Dedicated input region | Game above a lower portrait deck | Separates viewing from input, but needs a real renderer viewport and coordinated input geometry. |
| Edge controls | Side grips/rails in every orientation | Natural landscape reach; wastes useful width in portrait and can shrink the game excessively. |
| Contextual gestures | Hide most controls and infer actions from game state | Visually quiet, but this host lacks reliable on-foot/driving/action context; unsafe to imply working context-aware controls. |

Selected: conventional edge overlays in landscape plus a dedicated lower deck in
portrait, determined by the current window shape. The scene uses the entire window
when touch is disabled or a physical controller is active. Keep the existing
analog gamepad input semantics. Reject a decorative lower deck that merely covers
a full-height game image: that would hide the HUD and distort camera/input geometry.

## References and extracted qualities

- [Steam Deck hardware](https://www.steamdeck.com/en/hardware): group sticks,
  actions and shoulders by thumb reach; preserve simultaneous input.
- [Delta controllers](https://faq.deltaemulator.com/using-delta/controllers):
  separate touchscreen presentation from physical-controller presentation.
- [Apple game controls](https://developer.apple.com/design/human-interface-guidelines/game-controls):
  design touch controls around comfortable play and the content being viewed.
- [Apple Duo preparation](https://developer.apple.com/iphone-duo/prepare/): size
  from the live window and its safe area; test display transitions rather than
  identifying layouts from a device name.

Visual direction: graphite handheld hardware, a quiet divider between scene and
input surface, white controls with visible pressed states, restrained warm
selection colour on the home screen. The game remains the visual focus. Preserve
the host's existing typography and controller button language.

## Implementation plan and acceptance criteria

1. Share original layout geometry between native UI and synthetic preview/tests.
2. Give the Metal presenter a scene region while the overlay keeps the whole window.
3. Size the engine back buffer from that scene region; keep aspect ratio correct
   and clear held input when its size changes.
4. Support portrait and landscape orientations in SDL and app metadata.
5. Put all touch controls inside the portrait deck; ignore game-region touches as
   analog-stick starts. Preserve buttons, d-pad, both sticks, shoulders and menus.
6. Use a single-column home page in narrow windows and columns where space allows.
7. Inspect actual native control drawings at inner landscape, inner portrait and
   cover sizes. Check minimum button hit size, clipping/overlap and press/drag input.
8. Compile device ARM64, archive/export and verify the signature/SDK/version. If the
   new phone is not provisioned, distinguish a prepared build from installability.

Ready-to-test means all feasible source, geometry/input, visual and build checks
passed. It does not establish physical fold behaviour, thumb comfort, sustained
FPS, temperature or game compatibility. Those require the Duo later.

## Review record

Native layout preview is generated by `scripts/preview-duo.py`; it compiles the
actual ignored touch module against a synthetic input backend and renders its
vector shapes for inspection. The original scene illustration is synthetic and
must not be represented as GTA gameplay. Full native rendering/gameplay and
physical-device evidence remain separate.

Review findings, resulting changes, captured private evidence and final validation
are recorded here as checks complete.

### First bounded self-review

- The initial browser capture clipped the bottom of the device frame at a 720px
  browser height. Reduced the preview frame to fit the available browser height;
  this was a preview presentation issue, not a native layout change.
- The landscape resting movement stick crowded the lower-left HUD illustration.
  Moved its resting anchor upward while keeping floating-stick input. The compact
  cover preview was inspected after that change.
- Kept the portrait control deck rather than adding decorative panels. The
  controller preview removes it and exposes the full scene region.
- Corrected the synthetic scene preview to crop uniformly rather than stretching
  its illustration across changing aspect ratios. It remains synthetic evidence.
- Portable shared-Rust geometry checks: 15 cases, zero detected violations for
  the tested portrait controls at size 0.75/1.0/1.25, landscape full-window view,
  and controller full-window view. This is not a physical comfort test.
- Private screenshots: `.local/duo-portrait-preview.png`,
  `.local/duo-landscape-preview.png`, `.local/duo-cover-preview.png`.

### Final native review and verification — 31 October 2026

Xcode's first-launch setup is complete. The candidate compiled and exported with
iOS SDK 27.2. Its four declared Info.plist orientations, app version/build, strict code signature and
exported ZIP integrity were verified.

The native preview now renders the actual touch and page modules against
synthetic platform/input seams. Text uses native glyph positions and the local
upstream UI fonts; the synthetic scene remains separate from gameplay evidence.
Native home, video settings, compact scrolling and touch layout were inspected.

A second review found that compact settings shrank touch targets below 44 points
and made open-display settings unnecessarily small. Increased open-display
settings density and kept close, toggle, slider, choice and action targets at
least 44 points. The regression test checks those actual response rectangles at
both compact and normal density. Larger compact rows show fewer options at once;
the scrolling test verifies every video option becomes visible and remains within
the safe area. The resting landscape movement guide was moved above the HUD area;
its floating-stick interaction remains intact.

Verification: 17 repository tests; 20 native module/UI/input tests; 9
resize/presentation/workload checks; 2 compatibility checks. Geometry cases overlap
between harnesses and are not presented as independent benchmarks. A fresh pinned
checkout and the existing validated checkout produce identical patched Rust
source; repeat application is byte-idempotent. The original baseline app/IPA is
preserved. No game inputs, generated code, fonts, builds or screenshots are staged.

Final native-vector review captures remain private under `.local/` with the
`duo-native-` prefix. The prepared build is version 1.1 build 4. Its development
profile still needs the Duo registered. The owner has reconnected it; developer
support and account sign-in work, but Apple rejects registration because the
selected team has reached its iPhone device limit.
All physical fold, comfort, sustained performance and gameplay results remain pending.
